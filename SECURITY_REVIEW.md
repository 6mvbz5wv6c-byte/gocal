# FindOut backend review — 2026-10-05

Scope: Worker routes, D1 writes/schema, moderator authorization/concurrency, public forms, event evidence, calendar caching, and crawler extraction. This is a code review plus isolated attack/regression checks, not an independent penetration test or sustained load test.

## Implemented

- Native Cloudflare rate-limit bindings run before database access: 120 GET requests/minute/IP, 60 POST requests/minute/IP, and 3/minute/IP separately for submissions, reports and login. These counters are approximate and local to each Cloudflare location, not a global billing/security boundary. Anonymous IP limits can affect users sharing a network.
- D1 atomic quotas remain: submissions 5/hour/IP and 200/day globally; reports 5/hour/IP and 200/day globally; login 8/15 minutes/IP; authenticated moderation 600/hour/account. Agent ingestion allows 120 batches/day globally, max 20 candidates and 42 transactional statements per batch. This supports a monthly baseline scan without allowing the agent to approve events.
- Invalid/empty community forms and filled honeypots fail before submission quota writes. Date, start time, venue, address, description and HTTPS source are required. End time is optional. Supplied malformed/contradictory times still fail review. Browser autofill is useful to humans and is not disabled as an anti-bot measure.
- Turnstile client and server integration is prepared. When configured, validation checks success, exact request hostname, action, token size, and fails closed on verification outages or incomplete configuration. Cloudflare enforces five-minute, single-use tokens. The current account OAuth authorization cannot manage Turnstile widgets (403); **CAPTCHA is not active until keys are configured**.
- Public events cache for 30 seconds using a canonical key, ignoring arbitrary query strings. Local cache is invalidated after moderation/summary writes; other locations can display the previous result for at most the TTL. Admin/auth/evidence responses stay private and no-store.
- SQL values use prepared statements with bound parameters; the only dynamic SQL list is generated placeholders from internal field names. No submitted text becomes SQL syntax. The local integration fixture includes a SQL-like event title and verifies users, authentication and moderation still work.
- Body streaming stops at 64 KB. Input lengths, enums, dates, URLs, recurrence and evidence totals are bounded. There is no server URL-fetch proxy. Source text is rendered as escaped React text, never HTML. CSP restricts execution and embedding.
- Sessions are hashed server-side, Secure/HttpOnly/SameSite=Strict cookies; every protected request checks enabled user/role. Cross-origin mutation requests are rejected. Agent credentials have pending-only ingestion authority. Human approval and current revision are checked server-side.
- Guarded organizer/source/snapshot inserts now prevent orphan rows when duplicates or losing concurrent updates are ignored. Custody entries and evidence remain append-only. Added indexes for history by timestamp and audit by event.
- Cancellation in a title now blocks extractor readiness even if stale JSON-LD says EventScheduled. Nearby-city extraction requires an explicit allowlist. Public summaries exclude neighboring listings and private auditor notes.

## Remaining priorities

1. **Activate Turnstile** (free plan). Cloudflare Dashboard → Turnstile → Add widget, managed mode. Allow findout.events, www.findout.events and findout.6mvbz5wv6c.workers.dev. Then, from this repository, run `npx wrangler secret put TURNSTILE_SECRET_KEY` and `npx wrangler secret put TURNSTILE_SITE_KEY`, entering each value privately at the prompt. Both are necessary. Do not put secrets in Git or chat. Verify a real submission in a browser after setup. No test/bypass keys belong in production.
2. **Distributed denial of service / free-tier availability:** rotating IPs and distributed locations can bypass per-IP quotas or exhaust Worker invocations, D1 reads, login hashing or daily submission availability. Quotas prevent some storage abuse, not all denial of service. Configure appropriate zone-level managed protections and inspect their false positives; the current OAuth scope does not permit changing security policies. Keep Workers/D1 on the intended free tier; no automatic paid fallback. Confirm billing in the dashboard rather than assuming a hard dollar cap from this code.
3. **Admin MFA and recovery:** password-only login has no passkeys/TOTP/recovery workflow. Consider Cloudflare Access for the admin/API-admin surface or add passkeys with recovery/audit. PBKDF2 currently uses 100,000 iterations; review stronger password-hashing options against runtime constraints. IP-only login limits do not stop a distributed password-guessing campaign.
4. **Pagination and region partitioning:** admin list stops at 1,000 and public range at 2,000. Before multi-city growth, add keyset cursors, explicit region IDs/geographic policy and per-month API queries/indexes; show truncation rather than silently omitting data. Current named cities in venue records are not a complete geospatial model.
5. **Evidence/audit growth and recovery:** define retention/archival rules, database-size monitoring, encrypted off-device backups and a tested full restoration procedure. Current application export is intentionally partial; full D1 SQL export is needed for disaster recovery. Error logs have no alerting/SLO yet.
6. **Crawler:** no unattended local service is installed. Before 24/7 operation, add public-IP/redirect checks, fetch allowlists, download/time limits, retries with backoff, robots/terms handling, queue checkpoints, cancellation rechecks, fuzzy duplicate review and a dead-letter queue. Treat social text/model output as untrusted data, with no shell/tool authority or publication rights. Platform login walls remain blocked rather than bypassed.
7. **Data quality:** deterministic evidence coverage is not probability of truth. A source can contradict itself or label a canceled show as scheduled. Human approval remains necessary. Recurring holiday exceptions and exhibition opening hours need event-specific checks; a missing end must remain missing.

## Validation

`npm test` covers extraction, malformed evidence, dates/DST, optional end time, title cancellations, geographic scope, source-summary isolation, server-side challenge failures and pre-database rate rejection. Local API suites cover authentication, CSRF, SQL-like literal inputs, pending-only ingestion, approval without end time, revision races, immutable evidence, and summary updates preserving publication status. No production attack traffic or synthetic public events were created.
